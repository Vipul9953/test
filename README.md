You type a prompt. The app turns it into an **image**, a **landing page**, or an **email**. Each run shows up as a tile on the canvas and updates live.

Stack: Next.js App Router, TypeScript, Postgres, Drizzle, Groq (Vercel AI SDK). Live updates are **SSE** (`EventSource`). There is no WebSocket.

Images are **not** generated by a model. After a 20 second wait the tile gets a [picsum.photos](https://picsum.photos) URL (size from the aspect ratio you picked; if you picked none, the code defaults to 4:3).

---

## How this was built

Tables first, then the queue action, then streaming, then the UI.

The brief wanted a run log and an output row (with a parent for “improvise”). We added users, projects, and a wallet on top of that.

1. `dispatch_records` — one row per generate (prompt, kind, status, credit hold).
2. `creative_outputs` — the artifact JSON. `parent_id` is the older output if you improvised.
3. `users` + `projects` — each person has their own projects. First project is named `project1`.
4. `credit_accounts` — `available` and `held`. Hold / settle / release are real column updates.

Then:

- `dispatchCreative` server action — classify + insert `queued`, return a `runId`. It does not stream.
- `GET /api/runs/:runId/stream` — SSE. First subscriber starts the orchestrator (hold → render → persist → settle).
- Classifier, render, canvas tiles.

Schema and SQL live in `db/`. Apply them with `npm run db:migrate` (Drizzle Kit).

## What the product does

| Kind | What happens |
|---|---|
| Image | Tile stays on generating for **20 seconds**, then a picsum URL. Aspect / style come from the Image chips when you use them. During the wait the server emits a `partial` about once a second (`IMAGE_STREAM_TICK_MS`). |
| Landing page | Groq streams JSON copy. `lib/landing/normalize.ts` cleans it so it stays on your topic. Photos are fixed Unsplash URLs (`lib/landing/static-photos.ts`). |
| Email | Groq streams the email. A CTA URL is kept only if you typed one in the composer or brief. |

New account: **100** credits (`INITIAL_CREDITS` in `lib/constants.ts`).

Costs (`CREDIT_ESTIMATE`): image **4**, landing-page **10**, email **8**.

If `available` is lower than that cost, **no dispatch row is inserted**. The UI / action returns **Please subscribe**.

A finished landing tile (or **Open tab**) opens `/l/<runId>` with `window.open(..., "_blank")`. It does not navigate the studio away from `/`.

## Tables

```
users
  └── projects                  (name unique per user)
        └── dispatch_records    (the run)
              └── creative_outputs   (unique on dispatch_id)
                    └── parent_id → creative_outputs.id

credit_accounts                 (userId, available, held)
```

Defined in `db/schema/creatives.ts`, `users.ts`, `projects.ts`, `credits.ts`.

**dispatch_records**

- `status`: `queued` → `dispatched` → `completed` or `failed`
- `kind`: `image` \| `landing-page` \| `email`
- `intent_source`: `explicit` (you clicked a chip) or `classified` (Auto, or improvise locked to the parent)
- `credits_status`: `none` → `held` → `settled` or `released`
- `parent_artifact_id`: improvise from this output
- `phases` / `credit_phases`: JSON used by **Why this?**

Indexes: `(project_id, created_at)` for the canvas, `(user_id, created_at)` for credit activity.

## Postgres with Docker

`docker-compose.yml` only starts Postgres. It does not run the Next app.

```bash
docker compose up -d
```

Healthcheck is `pg_isready -U postgres -d skala`. Then:

```bash
npm run db:migrate
npm run dev
```

`npm run dev:up` is the same as migrate + `next dev`. It does **not** start Docker. Compose must already be up.

App: [http://localhost:3000](http://localhost:3000)

Sign up: a **new name** (2–32 chars) + **password** (4–64 chars). That creates the user, a `credit_accounts` row with 100, and a project named `project1`. Same name + correct password logs in again. Wrong password on an existing name fails.

```bash
docker compose down        # keep the skala_pg volume
docker compose down -v     # wipe the database volume
```

## Generate flow (what the code does)

```
ChatComposer
  → dispatchCreative()                 app/actions/dispatch-creative.ts
  → requireOperator() + Zod
  → queueCreativeDispatch()            services/dispatch.ts
       resolveIntent()                 services/classifier.ts
       if available < cost → { status: "credits" }  (no row)
       if ambiguous → { status: "ambiguous" }       (no row)
       else INSERT status=queued
  → { status: "queued", runId }

InFlightStreams / useRunStream
  → EventSource GET /api/runs/:runId/stream
  → subscribeToRun()                   services/run-hub.ts
  → runOrchestrator()                  services/orchestrator.ts
       emit classified
       hold credits
       emit dispatched
       renderCreative()                services/render/index.ts
       insert creative_outputs
       settle credits
       emit done
     (cancel / disconnect → release, emit error)
```

**Classifier** (`services/classifier.ts`), in order:

- Improvise (parent, no chip) → parent kind, no Groq
- Image / Landing / Email chip → that kind, no Groq
- Auto: reject very short / mixed / garbled prompts
- Auto: regex for email, landing, photo words
- Auto: `make` / `create` / `bana` with **no** kind word (e.g. “make kite”) → unclear, no row
- Auto: short noun phrase like “orange cat” → image, no Groq
- Else Groq. Confidence **below 0.6** → no row, no hold

## If it doesn’t start

- `DATABASE_URL is not set` — add `.env.local` and restart `npm run dev`.
- `GROQ_API_KEY is not set` — landing, email, and Auto paths that hit Groq fail. The **Image chip** still completes after the 20s delay (no Groq).
- Migrate errors / empty canvas — Postgres isn’t running, or you skipped `npm run db:migrate`.
- Port 5432 busy — another Postgres is bound. Stop it, or change the compose port **and** `DATABASE_URL`.
